# U-45「工具栏当前工具文字可读性」修复验证（audit-18 → audit-19 同区对照）

## 1. 结论

修复真实生效，且能被**同一像素区域**的前后对照直接证明：**字形颜色未变（峰值亮度逐帧一致）**，
差异集中在**字形本身及其新增的深色描边**，不是面板入场动画相位，也不是整体改色。

## 3. 量化指标

统一口径：像素差异 = `max(|ΔR|,|ΔG|,|ΔB|)`，阈值 `> 12`（与 `_frame-diff-vs-18-recomputed.txt` 的
`maxch_gt12%` 列、以及 `analysis/diffmasks/*.png` 中的白色像素**完全一致**，已逐帧核对）。

### 3.2 变暗 / 变亮像素分类（按 luma 口径，阈值 12）

| 帧 | 变暗像素 | 变亮像素 | 该帧工具名 |

### 3.4 修复前确实“难读”的客观来源

同区间在 audit-18 的 luma 分带直方图（11200 px）：

| 分带 | audit-18（修复前） | audit-19（修复后） |
| --- | --- | --- |
| luma < 40 | 2057 | 2063 |
| 40–70 | 8327 | 8547 |
| 70–100 | 814 | 588 |
| 100–130 | 2 | 2 |
| > 130 | 0 | 0 |

修复前字形主体落在 70–100 分带（814 px），而同一行背后面板底色也在 40–100 之间 →
**文字与背景只差约 1 个分带**，这就是“金色文字压在棕色面板上难读”的客观来源。
修复后 814 → 588（约 226 px 由 70–100 下移到 40–70 的描边带），轮廓对比建立。

（注意：本表统计的是同一 200×56 区间，其中 mixed 分带差异含描边压暗；单看 3.1/3.3 已足够定性。）

## 4. 与修复无关的既有特征（如实记录）

- 工具名文字**右端**在修复前后都结束于 x≈1579；工具栏面板右边界位于 x=1578（该列 luma 由 81 直降 25）。
  即文字右端紧贴面板内边界、基本无右内边距。**前后一致** → 既有布局特征，不是本次描边引入；
  也不是纵向裁切（首尾字形完整，见 `analysis/u45/rightend-context-2x_*.png` 与 `f3*_stacked_*.png`）。
- 本次修复只新增 `Shadow`（`effectColor` 0.10/0.07/0.05/0.85、`effectDistance` 1.5/-1.5、`useGraphicAlpha=true`），
  **未改**字号、锚点、颜色、布局。
