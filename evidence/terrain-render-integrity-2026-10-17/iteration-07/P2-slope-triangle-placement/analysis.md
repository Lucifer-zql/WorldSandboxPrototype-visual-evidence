# P2 三角坡路素材放置——官方结构核对与修复（iteration-07）

> 任务书 §四要求：重新核对官方素材用途；坡路必须嵌入高地顶面与悬崖连接结构；
> 不得仅以"方向映射正确/数量一致"关闭；须修复生产选片/放置条件。

## 一、官方结构核对（official-reference/official-B）

- 三角坡片（`Tilemap_color1..5` 的 c0r4/c3r4 = `_36`/`_39`）在官方示意图中位于**台地边缘墙排的端部/
  墙列之间**——是"从低地爬上台地的侧向坡道"，与墙列连成一体化边缘结构；
- **官方示意图中不存在"孤立摆在草地中央的三角片"**；
- 上下段 `_45`/`_48`（c0r5/c3r5）为草坡+青灰断面（台阶下段），与上段成对使用（D.5 语义保持）。

## 二、修复前缺陷（数据实证，三种子）

- 坡候选规则本身合法（E==0 低地格、东/西恰一侧 Hill、对侧低地干燥、临水不放、不邻 Mount）——
  **156/234/155 个坡格全部通过规则校验（0 违规）**；
- **缺陷**：坡候选与墙列**无结构关联**——真实孤立坡（3×3 内无任何坡/墙/台阶）**10 / 13 / 16 个**，
  另有仅对角连续坡 25 / 46 / 32 个。孤立坡在画面上即"独立三角装饰"（制作人指出的形态）；
- 另一连锁缺陷：坡格与南缘墙格**同格互斥**时（坡候选格恰好是南缘墙格）原先的"墙优先"会把坡
  整个消灭（无豁口语义）。

## 三、修复（生产代码，`TerrainOverlayPlan.cs`）

1. **执行顺序**：`CollectStairs → CollectSlopes → CollectWalls → PruneOverlapsUnderStairs →
   PostProcessSlopes → AssignWallVariants`——坡候选先于墙收集；
2. **墙收集跳过台阶格与坡候选格**（豁口语义：坡/台阶替代一段墙，不叠加、不删除应有的墙）；
3. **新增 `PostProcessSlopes`**：坡格南北邻（(x,y±1)）须有墙/坡/台阶（与边缘结构连续），否则
   剔除该坡并**补为墙格**（官方无孤立三角形态；该格本就是台地东西缘的低地格）；
4. 坡候选的其余条件保持不变（单侧高差/对侧干燥/临水不放/Mount 邻不放）。
