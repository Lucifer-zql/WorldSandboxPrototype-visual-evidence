## 二、根因（画面现象 → 素材 → 邻接条件 → 代码 → 根因）

### 2.1 素材事实（Python 逐像素实测，`Tilemap_color1.png` 576×384 = 9×6 格，PPU 64）

切片索引 `_N` = **行从图像顶部数**（PNG `x=(N%9)*64, y=(N//9)*64`）。崖壁四片的本质是
**(左缘渐出?, 右缘渐出?)** 的四种组合（左右缘各 4px 渐出到**透明**）：

| 片 | 左缘不透明行数 | 右缘不透明行数 | 语义 |
| --- | --- | --- | --- |
| `_41` / `_50` | 1,5,14,20,…（**渐出**） | 62,62,62,61,…（全实） | 仅左缘收口（左端帽） |
| `_42` / `_51` | 58,59,59,60,…（全实） | 63,63,63,62,…（全实） | **双缘全实 = 唯一无缝中段** |
| `_43` / `_52` | 58,58,58,58,…（全实） | 52,52,47,41,24,17,8,1（**渐出**） | 仅右缘收口（右端帽） |
| `_44` / `_53` | 1,5,14,20,…（**渐出**） | 59,58,52,44,26,17,8,1（**渐出**） | 双缘均收口（双端帽） |

`_41.._44` = 陆脚组（底缘暗收边+碎石）；`_50.._53` = 水脚组（底缘水线亮色，与陆脚同源）。
`_36/_39` = 台阶上段/侧坡片（直角三角形草坡）；`_45/_48` = 台阶下段。

> 导入设置经独立审计**全部正确**（PPU=64 / pivot 0.5,0.5 / Filter=Point / Sprite Multiple / 无 mipmap），
> 全部 tile `.asset` 引用**对位正确** ⇒ **不是导入/切片/引用问题**（Agent A 独立复核）。

### 2.2 缺陷 F1（阻断级）：长墙"中段"取到端帽片 ⇒ 每 64px 露透明缺口

**旧实现**（`TerrainOverlayPlan.AssignWallVariants`，修复前）：
- 把同 y 连续 x 段视为"一行段"；段首 → variant 0（`_41`）、段尾 → variant 2（`_43`）、孤立 → variant 3（`_44`）、
  **中段 → `VariantHash(锚x, 锚y) = (x*13+y*7)%4`**。
- 渲染层 `LayOverlays` 用 `TileAt([_41,_42,_43,_44], variant)` 取片 ⇒ **中段取值 0/2/3 时取到端帽片**，
  每个中段格左右各露出 **4px 透明渐出缺口**，透过缺口露出下层草地。
- 结果：长墙被切成**一排互相分离的相同石块**——与制作人反馈**逐像素吻合**。
  实测：种子 13 最长横段 = 9 格 → 7 个中段格全部 `_44`（双端帽）→ 每格两侧各 4px 缺口。
- 附带：旧规则**只识别横段**；对角/阶梯状高地边缘的墙格全部落为长度 1 的孤立段 → 一律双端帽 → 同样成排分离。

**修复**：端帽改由**实际相邻墙格推导**（含上下对角）——
`leftFull = 有墙于 (x-1,y-1)|(x-1,y)|(x-1,y+1)`，`rightFull` 同构；
两侧皆真 → variant 1（**无缝中段 `_42`**）；仅左缺 → 0；仅右缺 → 2；两侧皆缺 → 3。
墙格集合、row(4/5) 判定、输出顺序、`CliffWallCell` 数组契约**均未变**。

### 2.3 缺陷 F2（P1）：水脚墙格被叠加泡沫 ⇒ 与墙脚自带水线成"双线"

**证据**：`WaterFoamRenderer.NeedsFoam` 只判「Grass/Forest 且 4 邻有水」，**不引用覆盖计划**；
而水脚墙格 = 高地南缘下方**临水陆格**，本身是 Grass ⇒ 被判 true。
规范 §D.2 明文「**崖格不放**（水脚件自带烘焙水线）」——新模型未落实该语义。

**修复**：`WaterFoamRenderer` 新增 `SetPlan(TerrainOverlayPlan)`，绑定 store 后构建
**水脚墙格（Row≥5）索引集**，`NeedsFoam` 对命中格返回 false；`GameBootstrap` 接线
（`SetPlan(result.OverlayPlan)` 后 `RebuildAll(terrain)`）。计划为 null（旧存档/未接线）**退化为旧口径**。
用独立 setter 而非 `RebuildAll` 重载——避免既有反射式测试按方法名取方法时 `AmbiguousMatchException`。
